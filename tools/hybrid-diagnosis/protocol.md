# Retrospective hybrid diagnosis and one controlled experiment

This investigation follows the completed study at `f459085`. All preceding datasets, models, solver sources, journals and archives remain immutable. The former 252-input fresh test is retrospective diagnostic evidence; it is not used for new fitting, checkpoint selection, a new holdout claim or routing decisions.

The initial scripts produced exploratory case, training and support analyses. `analyze_cases_v2.py` supersedes the first case analysis's broad budget-word search, implicit negative fallback inference and single-block grouping. It explicitly separates observed iteration, neural-time and whole-request limit evidence; unknown evidence remains unknown. It records both blocks, reference and candidate stability, and the owner of terminal FIRST diagnostics. A separate ONLY request is not described as the internal neural trajectory of FIRST. It also compares each pipeline's own raw and post-preparation states, separately from incumbent comparisons.

`analyze_training_v2.py` adds the frozen incumbent on the same original 805 TRAIN, added 101 TRAIN and original 168 certified validation profiles, predicted-branch anchor conditioning, correlations, standardized tails and exact exposure bounds. The initial training analysis is preserved as exploratory evidence. Original checkpoints are checked against sealed manifests before restricted loading in the refined analyses. Exact-zero support counts, above-decoder-floor omissions and presence-head decisions are reported separately. Native support refresh can subsequently change these seeds.

The source-hashed `ablation-plan.json` was frozen before either new fit or new panel prediction. It allows exactly two fits on N with seed 20260911 and 4,160 optimizer updates. The empirical control retains its original support means/scales. The canonical alternative changes only output coordinates 45–84 to mean zero and scale one, with initial last-layer weights and biases transformed by `W'=sW`, `b'=sb+m`. This preserves initial physical logits and decoded masks. Architecture, continuous reconstruction, labels, minibatch order, loss, optimizer settings, clipping, threshold, trace policy, material wrapper and native solver are unchanged. The parameter-coordinate change still affects AdamW regularization and global clipping; that is part of the tested optimization treatment.

Both fits use the original 168-reference minimum-score checkpoint rule; final checkpoints and their scores are also retained. Exact minibatch-order hashes and per-case presentation counts must match. Export parity uses the same fourteen original TRAIN fixtures, native tolerances, exact branch/wet/zero masks and ten-worker cancellation/repeatability checks.

The diagnostic panel contains sixteen validation inputs from each of the four old incumbent-versus-N neural-only outcome groups, chosen by a fixed input-ID hash, plus the rare liquid-only validation reference if absent. The resulting 65 inputs were selected before evaluating the new models. Three pipelines—incumbent, empirical and canonical—receive all three solver modes in two reverse-order blocks. The exact frozen evaluation probe supplies ten owned workers, a 30-second request deadline, two-second neural budget, sixteen correction iterations and a 4 GiB Java 21 process.

Request accounting is **1,170 measured panel requests**, plus **36 fixed original-TRAIN warmup requests** from that unchanged probe (two repetitions of three modes per pipeline run). The registration's `maximumCorrectedRequests` field refers to measured panel requests. Parity comparisons and prediction/property analyses contain no corrected column requests. The panel is deliberately outcome-stratified: its percentages are not whole-population performance estimates. No model promotion is allowed.

The conditional preparation-on/off experiment is skipped because none of the selected hybrids' incumbent-only validation losses was PREPARED. No additional training family, extra seed, threshold search, exposure extension or former-test model evaluation is permitted in this investigation.

The final report distinguishes supported findings, weakened explanations and unresolved causal questions. Every analysis input is bound to its source or previous archive, native runs are revalidated, the reproduced control is checked against its original checkpoint, and report outputs are recomputed before a new diagnosis archive is sealed outside `build/`.
