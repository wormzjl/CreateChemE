# Alternatives to Newton for CreateChemE

Investigation dates: 8–9 September 2026. Scope: the current V3 distillation-column equations, with the registered `createcheme:tjl19_dwsim` property package. This is a research recommendation and an isolated diagnostic comparison, not a production solver replacement. The working tree already contained a TJL19 migration; the investigation used those current files and preserved the existing changes. Base commit: `e8d8937eacc1d58692f1a4f289f0633ec25b4cd1` plus the working-tree changes.

**Keep the current accepted solver as the baseline. For a genuinely derivative-free comparison, test DF-SANE on the full residual; for reducing repeated Jacobian work, test guarded chord reuse followed by limited-memory Broyden.** Chord and Broyden remain Newton-family methods. A complete sequential material/energy map with Anderson acceleration is a promising structural research direction, but the existing Sum-Rates routine is not ready to serve that role. Inside-out is a larger, longer-term column-formulation alternative. None of the proposed new algorithms has yet demonstrated a production performance advantage in this project.

Before pursuing Anderson on the sequential route, qualify the iteration itself. The existing Sum-Rates code is only a bounded seed generator, rejects side draws, and is not wired into the calculator. Accelerating it without establishing a useful fixed-point map would be premature. The diagnostic results below test that prerequisite and revise the initial preference for starting with that existing seed strategy.

The strongest additional deduction in plan 2 is a map-contract counterexample. The material/bubble-point projection does not use the specified reboiler duty or prescribed stage heat. Changing only a duty can leave that projection unchanged while changing the MESH energy residual. Its fixed points therefore cannot, in general, characterize the roots of every requested energy-balance problem. Its name also says “fixed temperature,” while the implementation calls a bubble-point temperature update. Read the executed operations rather than infer behavior from that name.

The second review also identifies a real cost to measure: for 30 trays plus the reboiler, the current Sum-Rates temperature correction can request 31 whole-column perturbation evaluations per sweep, or 372 over its maximum 12 sweeps, before other work. A nominal fully populated 19-component dry three-color Jacobian has 234 plus/minus perturbation evaluations plus its base evaluation. These are code-derived counts under stated conditions, not timings or equivalent units of nonlinear progress; support reduction, actual sweep counts, failed probes and final correction change the comparison.

Plan 2's next bounded experiment should validate a known root and a duty-change negative control, then add **one** residual-only comparator. For DF-SANE, define a dimensionless function such as `h(z) = P D0^-1 F(q_ref + C z)`, where the fixed residual scales `D0`, coordinate scales `C`, and residual ordering transform `P` are explicit and nonsingular. This preserves roots on the fixed admissible domain, but does not prove convergence. Implement the method's own documented nonmonotone search; do not silently replace it with Newton's Armijo rule. Separately report its raw full-residual outcome and any subsequent rigorous-correction/audit outcome.

Anderson on a reduced vector has an additional prerequisite: temperatures and phase totals do not uniquely determine PR fugacity coefficients without compositions. Define a converged composition reconstruction or retain the required state variables. Repeating a history-dependent seed wrapper is not automatically a well-defined reduced map. These requirements make the revised plan feasible as a falsifiable investigation, while making a direct production switch premature.

In its subsequent source/API review, 6 Pro confirmed that there is no remaining feasibility blocker for this bounded future plan. Longer chord/Broyden reuse needs a benchmark-local driver because the production reuse cap is one; a cached Jacobian still incurs factorization through the existing API. All stored history must use one fixed residual scaling epoch, and changes to equation/unknown identities require a restart even when vector length is unchanged. The existing solve entry point can supply the final correction certificate, so no fabricated evidence or access to its private verifier is needed. These are implementation prerequisites, not claims that the proposed methods have been implemented or will outperform the baseline.

The mathematical task is solving a square nonlinear system, `F(q) = 0`, rather than minimizing an economic operating objective. The coordinates contain positive component flows represented logarithmically and temperatures represented in kelvin. The residual includes component material balances, vapor–liquid equilibrium, energy balances, and water saturation where applicable. An optimizer can minimize `phi(q) = 1/2 ||D F(q)||²`, but a small gradient or small step can occur with a nonzero balance error. Every candidate must still pass the actual residual and physical acceptance checks.

The certificate requires a final linear backward error at most `1e-12`, a log-flow correction within the selected closure, and temperature changes within `1e-6 K + 1e-9*T` per coordinate. Although its field is named `hasFinalNewtonStep`, the verification routine can try damped normal-equation corrections after a direct fine-Jacobian correction; “unchanged final correction certificate” is more precise than claiming every certified step is pure unregularized Newton. The default closure is `1e-8`; supported authored closures extend to `1e-3`. Logarithmic flow coordinates do not remove phase-domain restrictions. Condenser branch, trace support, and wet-tray sets can change in the outer recovery logic and can change the system being solved.

These are engineering priorities inferred from the current architecture, not measured rankings between implementations of all these algorithms.

Anderson acceleration combines a small history of fixed-point updates using a least-squares problem. SUNDIALS implements it for both fixed-point and Picard iteration, including damping and QR-based history solves. That provides a concrete numerical reference for an implementation. [SUNDIALS mathematical description](https://sundials.readthedocs.io/en/latest/kinsol/Mathematics_link.html#anderson-acceleration), [KINSOL controls](https://sundials.readthedocs.io/en/latest/kinsol/Usage/index.html).

For CreateChemE, first expose a deterministic single material/energy sweep `G`, preferably on a reduced vector of stage temperatures and phase traffic. Confirm that an exact MESH solution is a fixed point and that convergence of this map addresses all required equations. The current bubble-point routine includes a local Newton temperature correction; the current Sum-Rates routine uses a linearized energy-temperature correction. Thus an Anderson outer loop is not a promise that no Newton-like calculation occurs anywhere inside it. The final publication certificate would also still use Newton in the initial experiment.

Use history lengths 3 and 5 as initial experimental settings, a separate temperature scale, damping, and rank-aware QR or regularization. Reconstruct component flows through the material solve using `V_i/L_i = K_i * V_total/L_total`; the code explicitly distinguishes these ratios. Reject invalid phases, nonfinite coordinates, or an accelerated trial that fails the same frozen-scale MESH-merit safeguard. Restart history after any topology, phase branch, support, wet set or operating-rung change. A small fixed-point update must never substitute for checking the full MESH residual.

Inside-out is a formulation change rather than a generic minimizer. Boston and Sullivan's original method uses energy/volatility parameters and Broyden iteration on stage-related variables. It is therefore inaccurate to call all inside-out implementations Newton-free. [Boston and Sullivan (1974)](https://onlinelibrary.wiley.com/doi/abs/10.1002/cjce.5450520108). DWSIM's documentation separately identifies Sum-Rates, bubble-point and simultaneous-correction methods; the last explicitly uses Newton linearization. [DWSIM column solving methods](https://dwsim.org/api_help/html/N_DWSIM_UnitOperations_UnitOperations_Auxiliary_SepOps_SolvingMethods.htm).

An inside-out prototype here would update local PR equilibrium and enthalpy approximations outside a cheaper material/energy solve and always verify the final state with the rigorous property package. Phase disappearance requires explicit treatment: published nonsmooth inside-out work addresses dry/vaporless stages, but one formulation also permits a flexible operating specification to be reset. That behavior must not be imported into this project without an explicit product decision; convergence must not silently alter the user's reflux, duty or draw specifications. [Cavalcanti and Barton, phase-disappearance study](https://www.sintef.no/globalassets/project/higheff/deliverables-2020/d1.2_2020.01-distillation-simulation-robust-to-liquid-and-vapor-phase-disappearing.pdf).

Broyden learns a Jacobian approximation from accepted changes in state and residual rather than differentiating every iteration. PETSc documents limited-memory Broyden variants, restart policies and nonlinear preconditioning. [PETSc SNESQN](https://petsc.org/main/manualpages/SNES/SNESQN/). The implementation experiment should retain the stage-banded base solve and store only bounded low-rank corrections. Ordinary dense rank-one updates destroy strict band structure; simply dropping off-band entries also changes the secant condition. Residual differences must use consistent scales across the history, with rescaling or a restart when necessary. Test this separately from Anderson to identify which mechanism supplies any benefit.

A guarded chord experiment is a simpler precursor: reuse a Jacobian across accepted steps and refresh after poor progress. However, the current [banded solver](D:/Minecraft/Modding/1.21/CreateChemE/src/main/java/com/wormzjl/createcheme/science/column/v3/linalg/V3BandedPivotedSolver.java) factors afresh inside each `solve` call and exposes no reusable factorization object. Reusing a Jacobian therefore does not automatically reuse its LU factors. The simultaneous solver also explicitly caps its existing frozen-Jacobian path at one reused step. Longer reuse requires an isolated experimental loop or a deliberate API change, not merely setting a presently available configuration option.

Adaptive LM would minimize the local model `1/2 ||r + J*p||²` with a scaled step bound or adaptive regularization. Compare actual and predicted reduction using the same frozen row scales for both; adjust the radius/damping from that ratio. The current solver already forms `JᵀJ + lambda*diag(max(1, diag(JᵀJ)))`. For difficult conditioning, an augmented least-squares solve using QR is worth comparing against explicitly formed normal equations, whose unregularized condition number is squared. A rank-deficient case is not a reason to choose every dogleg implementation indiscriminately: SciPy specifically cautions against its `dogbox` method for that case. [SciPy least-squares methods](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.least_squares.html), [PETSc trust-region implementation](https://petsc.org/main/manualpages/SNES/SNESNEWTONTR/).

For implicit pseudo-transient continuation, a representative step solves `(M/dt + J)*p = -F`. Defining `M` is substantive work in a mixed material/energy/algebraic system. Adding an identity matrix in the current arbitrary residual/coordinate ordering does not establish a physically sensible or stable pseudo-dynamics. PETSc's method uses a shifted Jacobian and linearly implicit Euler; explicit relaxation is a different tradeoff and may need very many steps. [PETSc TSPSEUDO](https://petsc.org/main/manualpages/TS/TSPSEUDO/).

DF-SANE uses a spectral residual direction and a nonmonotone line search without gradient information. It is a legitimate derivative-free root-finding comparator, unlike treating every derivative-free method as a generic optimizer. [SciPy DF-SANE](https://docs.scipy.org/doc/scipy/reference/optimize.root-dfsane.html). For the full MESH system I would give Nelder–Mead, population methods and generic coordinate search lower priority: they give up the available stage structure and can spend many PR evaluations reducing a scalar merit while some balances remain unacceptable. They may be relevant to a later low-dimensional outer operating-design problem, which is a different task.

The isolated [probe source](D:/Minecraft/Modding/1.21/CreateChemE/benchmarks/solver-alternatives/V3SolverAlternativesProbe.java) compares fine correction, continuation-local-block correction, Sum-Rates plus fine correction, Hybrid plus fine correction, and bubble-point projection plus fine correction. It reads the current Java test fixtures directly through narrowly scoped research-only reflection, avoiding copied or relabeled assay vectors and production access changes. The three inner cases are the current four-stage crude fixture, the current two-stage Sum-Rates binary fixture, and the floor-supported restart of the current TJL19 wet pinned state. The last is already covered by a support-remedy regression; it is not presented as a newly discovered production stall.

Each case gets one warmup and three measured serial repetitions, with rotated variant order and a five-second cooperative limit per attempt. Common fixture/initial-seed construction is excluded from per-attempt timing; sequential preparation, correction, final residual calculation and fresh audit are included. A failed or inapplicable preconditioner falls back to the original seed and is explicitly labeled. A run counts as accepted only if the correction converges, its existing certificate passes and the fresh audit accepts. Timeout results are censored failures, not fast solves. Jacobian callbacks omit some final certification work; checkpoint counts are cancellation opportunities, not FLOP or property-call counts.

`LOCAL_BLOCKS` names the selected solver entry point, not proof that local-block directions executed. The binary fixture has 19 coordinates, below the 96-coordinate activation threshold. Its measured runs recorded zero accepted or rejected local directions, 121 fresh-Jacobian callbacks, and 43 reuse callbacks. This is evidence about the reuse-enabled entry point, not a test of local-block directions on the binary case. The one-step cap limits consecutive reuse of an anchored Jacobian, not total reuse callbacks across a solve.

The wet restart needed three observed fine-Jacobian builds on the fine path and three accepted local directions with zero observed fine-Jacobian callbacks on the local-block path. Both still passed final Newton certification and the full fresh audit, and their times were effectively equal at this resolution. The callback difference does not prove that total expensive work fell: the final verification work is not fully represented in that hook.

The binary fine-correction attempt reached a residual of about `3.55e-15` but failed the certificate and physical audit. This is a concrete reason to retain both gates rather than declaring success from the residual alone. The four-stage probe fine path ended at residual approximately `0.784`; this standalone probe passes the full feed-flow vector into the feed TP flash, whereas the original unit probe passes normalized composition. Its trajectory must not be equated with the separate unit-test trajectory. Within the comparison, every variant receives the same fixed problem, feed enthalpy and initial seed.

**Decision from this pilot: do not wire the existing Sum-Rates/Hybrid seed routine into production or add Anderson around it unchanged.** No measured case demonstrated an accepted gain attributable to those seed strategies. First qualify a complete sequential map and its support/phase handling. The wet projection failure is an applicability warning for this direct composition of routines, not evidence that the normal production path invokes that invalid composition. Broyden, Anderson, inside-out, adaptive LM, JFNK and DF-SANE were researched but not implemented or timed in this pilot.

The recommended follow-up experiment has these acceptance conditions:

1. Run map-contract diagnostics on the existing preparation routines: known-root preservation, a duty-change negative control, full residual versus update size, and wet/support/side-draw applicability. These diagnostics can reject a routine as a complete root map; they do not require constructing a new sequential solver first. Preserve positive-flow and structural-zero behavior and never bypass `NotApplicable`.
2. Add one bounded DF-SANE comparator on the full current residual, with explicit coordinate scales, fixed residual scales and ordering, its own nonmonotone search, and domain/cancellation handling. Record its raw residual outcome separately from subsequent rigorous correction and fresh audit. Charge all cleanup cost. Stop this research batch after those diagnostics, that one comparator and an updated recommendation.
3. Choose any later implementation from measured evidence. If Jacobian construction is a material cost, test isolated guarded chord reuse before adding limited-memory Broyden. Only pursue Anderson after qualifying a complete sequential map and its state/composition reconstruction; compare the unaccelerated map first. Defer JFNK until system size justifies extra Krylov/property work, and adaptive LM until traces implicate globalization. These are conditional follow-ups, not additional algorithms to implement in the next bounded batch.
4. Use the current TJL19 A–E matrix, dry binary/manufactured checks, the current pinned floor-support case, low-pressure/phase-boundary cases and invalid-domain cases. Keep cutoff, closure, topology, input specifications, property revision and seed policy identical between comparisons. Use the Holland Example 3-2 independent oracle when a new numerical algorithm is implemented; it was not rerun for this read-only production investigation.
5. Collect end-to-end cold and warm distributions in separate experiments. Include failed attempts, all continuation rungs, property calls, Jacobian builds, factorization/iteration work, allocation/GC, cancellation latency and final audit. Record JVM and machine context. Use multiple independent JVM runs before making deployment claims; three repeats in one JVM are only a diagnostic screen.
6. A proposed performance threshold is at least 25% lower median cost on the targeted expensive accepted cases with no new failures and no more than 10% regression on the other accepted cases. A robustness win requires a newly accepted result under the same resource and physical gates. These are proposed decision thresholds, not measured outcomes or guarantees.
